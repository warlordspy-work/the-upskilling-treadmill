Cloud Run Service Spec: Networking & Concurrency

info Architecture Objective

By default, Cloud Run passes incoming ingress traffic on the container's designated listener port. Mismatching this manifest declaration causes critical 502 Bad Gateway cold starts and instant container starvation.

checklist Implementation Steps

1

Specify the Ingress Container Port

Update the specification in service.yaml under the ports block to expose port 8080.

containerPort: 8080
2

Tune Container Memory & Concurrency

Prevent out-of-memory container crashes under sudden traffic spikes. Allocate 512Mi memory limit and explicitly lock concurrency to 80 requests per instance.

3

Simulate Deployment & Verify Telemetry

Click the Run Code ▶ button in the right-hand panel to compile the manifest and pass the 3 health probe assertions.

gcloud run deploy microlearning-srv --image=gcr.io/...
lightbulb Need a hint? Check the service.yaml memory allocation syntax expand_more

Ensure resources are bounded under the limits block inside your container spec:

resources:
  limits:
    memory: 512Mi
    cpu: "1000m"
verified

Key Takeaway

Cloud Run automatically scales to zero when no active requests are pending unless min-instances is configured to eliminate cold start penalties.

Why did my previous container fail health checks on port 3000?
bolt

Cloud Run defaults to listening on PORT 8080.

You mapped 3000 in your Dockerfile without setting the PORT environment variable. Updating line 18 to containerPort: 8080 resolves this instantly.
